# 官网多人协作开发约定

当前工作基于已确认的首页 V1.46。首页继续由主线负责人打磨；产品、行业、价格与下载页面可以独立开发。框架继续使用 Astro + TypeScript 静态构建，不引入第二套路由或 UI 框架。

## 先运行自己的页面

使用 Node.js 22.23.4 或更高版本，执行 `npm ci`、`npm run dev`，打开下表对应地址。本地固定使用 4350，启动脚本会清理占用该端口的旧预览。不同同事在各自电脑开发。

从 `feat/navigation-architecture` 建立自己的功能分支。一个提交集中在一个页面或模块；共享文件变更单独提交，并由主线负责人合并。

## 在自己的目录里开发

每个产品或行业目录有两个文件：

- `content.ts`：该页面的中英文内容、稳定 slug、排序和菜单图标。
- `Page.astro`：该页面正文，接收 `locale`。可替换现有共享正文模板，自由组合本页组件和局部样式。

页面外壳由路由统一提供，`Page.astro` 不重复渲染 `Layout`、header、footer、`main`、canonical。页面组件按 `locale` 选择内容。

当前产品与行业模块通过 `import.meta.glob` 自动发现。新增模块同时添加 `content.ts` 和 `Page.astro`；匹配各自 `types.ts` 契约后，路由及下拉入口会自动生成，无需多人修改同一个注册数组。`slug` 必须等于目录名且全站唯一；`order` 决定菜单排序。行业 `category` 为 `industry`、`general` 或 `deployment`，分别用于行业主清单、保留的通用页面或专属部署分组。

模块内组件放在本目录 `components/`；样式优先使用 Astro 的局部 `<style>`。图片放到 `public/images/product/<slug>/` 或 `public/images/solutions/<slug>/`，版本化命名。页面用根路径引用图片，避免修改共享素材。中英文页面共用同一 slug。

## 共享文件由主线维护

| 文件或目录 | 作用 |
| --- | --- |
| `src/components/navigation/`、`src/styles/navigation.css` | 桌面与移动导航，点击展开、键盘关闭、透明与滚动态 |
| `src/layouts/Layout.astro`、`src/lib/site.ts` | 页面外壳、页脚、外链、SEO 与通用路径 |
| `src/components/pages/` | 初始能力页和行业页正文模板 |
| `src/features/product/types.ts`、`src/features/solutions/types.ts` | 模块数据契约 |
| `src/pages/` | 统一路由与构建入口 |
| `src/components/HomePage.astro` 与首页视觉组件、既有全局 CSS | 已确认首页与继续打磨的主线工作 |
| `src/data/legacy.ts`、`public/releases/`、`src/content/blog/` | 原发行、法律与历史文章，不跟随内页改版重写 |

如某页面需要不同布局，直接改自己的 `Page.astro`，无需改共享模板。涉及导航、契约或全局样式的需求先交给主线整合，避免影响其他页面。

## 导航与旧入口承接

顶层固定为产品能力、解决方案、价格、文档中心、资源下载、博客。前两项为点击展开，其余直接跳转。产品下拉仅显示图标与名称，不增加下拉辅助入口。产品总览、开放生态和企业部署沿用原页面及页脚入口。解决方案主区为六行业，一体机位于专属部署分组，不增加额外菜单入口。通用办公继续由首页及页脚进入，方案总览原地址保留。

产品总览、全部解决方案、开放生态、企业部署、资源中心、历史版本、FAQ、联系与法律页面继续可达。原博客页面和 RSS 保留，顶部和页脚博客入口按指定地址跳到 `https://www.zhama.com/zh/blog`。文档中心链接固定为 `https://docs.zhama.com.cn/`。

首页行业页签继续保留已确认的五项和原顺序；新行业进入导航及解决方案总览，不自动扩充首页。

## 价格与下载的事实边界

价格采用已确认的报价咨询版。`src/features/pricing/content.ts` 集中管理三种应用方案的报价要素；真实金额、计费单位、包含范围、有效期确认后再发布。不把当前方案卡片称为已经确定的正式套餐。

下载模块沿用真实发行清单。`resources.ts` 从 `public/releases/index.json` 读取服务端版本和清单路径。镜像和部署包从既有历史版本页选择；发布清单链接不是镜像文件本身。新增客户端、鸿蒙包或镜像必须有对应发布记录及可用地址，不能只增加下载按钮。

## 提交前检查

1. 执行 `npm run check`、`npm run build`、`npm run verify`。
2. 打开负责页面的中英文地址，检查菜单入口、CTA、图片、手机宽度与无横向溢出。
3. 核对正文事实、术语、授权条件及所有下载地址。不提交凭证、内部资料、运行缓存或截图目录。
4. 提交自己的模块与所需新素材。共享文件变更说明影响范围并单独提交。

自动检查可验证构建、链接和结构，不能替代业务审稿或真人可用性测试。
