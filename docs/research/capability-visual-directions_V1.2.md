# 产品能力页视觉表达调研与采用建议

访问与记录日期：2026-11-15（Asia/Shanghai）。

范围：六个产品能力页的概念配图与核心能力区。本文为内部研究记录，不改写已认可首页，不向页面添加研究旁白、说明小字或辅助入口。

## 调研方式与实际取得的材料

已阅读 agent-reach 技能及其 search/web 路由。当前 mcporter 没有配置 Exa 服务；Jina Reader 请求超时，因此改为直接获取公开第一方 HTML，以 parse5 提取正文、标题和图片说明，并下载与检查页面直接引用的视觉资产。未使用浏览器，未进行竞品真人体验或交互测试。

已实际打开并阅读全文中相关段落的品牌为 Glean、Dust、Relevance AI。Relevance AI 的 `/ai-workforce` 返回 404，未作为有效依据，随后改读其官网首页。

## 来源与具体观察

### Glean：用能力场景拆分表达，不让一张图承担全部架构

来源：[Glean Agents](https://www.glean.com/ai-agents)。原请求 `https://www.glean.com/product/agents` 的页面 canonical 指向该地址。

页面将 Agent 生命周期拆为四个主要段落：编排、构建测试、部署分享、观察改进。段落标题分别是 “Orchestrate agents across workflows.”、“Build, test, and iterate with ease.”、“Drive the right adoption with control.”、“Monitor and improve agent performance.”。每段围绕一个动作，配一个对应视觉，而非将所有能力、系统和收益放进同一张总览图。

实际检查的 [Orchestration Desktop 资产](https://cdn.prod.website-files.com/6127a84dfe068e153ef20572/6a8e6ee2b7eb558883704204_Agents%20Orchestration%20Desktop.png) 是周期任务设置的单一界面特写，展示开始时间、重复频率和投递位置。它的价值在于具体展示一个操作关系；并非复杂网络或抽象发光核心。不能仅凭资产名称将其描述为编排架构图。

采用：每个 TeGo 能力页只确立一个核心视觉关系；需要表达任务调度时展示任务、周期、结果之间的关系。核心能力的文字与图片分工，图不重复写正文。

不采用：白色大表单、竞品 UI 组件、竞品品牌和现成图像，以及页面上的收益数字。该视觉只能证明 Glean 的公开展示方式，不能证明 TeGo 具有相同设置项或投递渠道。

### Glean 治理：先解释治理对象，再表达安全感

来源：[Glean Agent Governance](https://www.glean.com/ai-agents/agent-governance)。

正文分开陈述 Agent 分享范围、每次请求的数据权限检查和行为范围约束。它不是笼统写“企业级安全”，而是解释管理员决定分享上限、创建者在边界内选择分享对象，以及请求按使用者权限读取资料。

实际检查的 [Dynamic Intelligence Desktop 资产](https://cdn.prod.website-files.com/6127a84dfe068e153ef20572/6a8e7fc92582ebea27326ebe_Agent%20Governance%20Dynamic%20Intelligence%20Desktop.png) 使用中心盾牌与周围 Agent/数据源连接。关系清晰，但盾牌、图标和虚线的外观不适合直接搬入当前 TeGo 站点，尤其用户已拒绝廉价图标堆砌。

采用：让治理图具体显示“身份/授权范围如何作用于数字员工执行”，同时保留可回看的执行记录。边界是业务关系，不是四处摆放锁头。

不采用：Glean 的 alignment models、每一步权限执行等产品机制作为 TeGo 事实；TeGo 的准确范围仍使用当前源码中的 LDAP / OIDC、业务委托、审核管理、执行审计。

### Dust：协作的主体是人、Agent 与共同工作内容

来源：[Dust 官网](https://dust.tt/)。

当前首页主标题为 “Multiplayer AI for human-agent collaboration”。正文强调公司知识、工具和团队共同进入真实工作流；协作段落具体列出共享知识、连接工具、会话和通知，人员负责引导工作。治理段落把“Agent 可以访问什么”与“谁可以使用 Agent”分开。

实际检查的 [team-sport-collab.svg](https://dust.tt/static/landing/home/team-sport-collab.svg) 以一段会话/输入区域作为主体，出现被 @ 的同事和具名协作者，表达同一内容上有人与 Agent 参与。图中带协作者光标与模型选择器，这些只是 Dust 的公开表达，不能成为 TeGo 的界面或功能依据。

采用：协作页配图以共同项目或成果为中心，人员、数字员工和交接记录围绕同一个工作对象。比“几个人物头像分别装在独立卡片里”更能说明协作。权限概念要分清，不把使用权限、知识权限、工具委托合成一个开关。

不采用：多人实时光标、协同编辑冲突处理、SCIM、zero privilege escalation 等未经本产品验证的能力，也不复制模型图标和装饰性分享控件。

### Dust 知识：问答与来源的关系比数据库/大脑造型更直观

来源：[Dust for Knowledge](https://dust.tt/home/solutions/knowledge)。

页面从企业知识可获取入手，展开团队知识问答、产品专家、活动摘要、行业雷达等用途。知识不是单独的数据仓库造型，而是可被人在任务中使用的内容。

实际检查的 [Team knowledge / askacme.png](https://dust.tt/static/landing/knowledge/askacme.png) 把一个问题、一个回答及其引用来源直接关联起来。视觉表达的重点是“答案来自内部知识”，不是满屏文件缩略图。

采用：TeGo 知识图使用少量资料层、选中的原文片段和与其关联的成果片段，展示资料成为依据。引用关系只要一处清楚即可，不用把检索算法、索引、权限全塞进图里。

不采用：竞品客户信息、Slack UI、历史日期、用户比例和节省时间数据；也不照搬其业务语料。

### Relevance AI：用明确职责说明数字员工，而不是机器人外形

来源：[Relevance AI 官网](https://relevanceai.com/)。

当前首页先讲从人员经验到可运行系统，再列出命名明确的专业 Agent，例如 Research & Enricher、Pre-meeting Prepper、Post-call Actioner、Proposal Builder。每个角色附一条具体职责，如会前整理背景、会后记录与跟进、生成定制方案。治理则另列访问控制、审计和监控。

采用：数字员工页应让人识别“这是承担职责、使用资料、产生成果的工作角色”。角色与工作对象一同出现，少量真实感职业头像可以加强员工感；不靠机器人、发光球体或抽象 AI 大脑证明“智能”。多 Agent 页则用明确专业分工和结果归集区别于岗位页。

不采用：其客户案例、连接器数量、模型自动切换、自我评估、自主等级和交付时长作为 TeGo 承诺。其网站也使用角色卡片；本项目采用的是职责表达，不照搬满屏卡片布局。

## 与 TeGo 当前内容的对照

本次读取六页 `src/features/product/*/landing.ts`，仅将其中已有能力作为图稿语义依据。没有通过网站源码验证产品后台，因此以下是对当前网站内容的设计映射，不是新一轮产品功能验收结论。

| 页面 | 当前内容中的核心关系 | 图稿必须避免暗示的能力 |
| --- | --- | --- |
| digital-employees | 静态岗位模板沉淀职责/技能/文件，招募后成为独立数字员工，执行周期工作并积累个人工作记忆 | 模板等于运行实例、无条件自动审批、多个使用者共享私人记忆 |

| collaboration | 项目成员、资料、会话、事项与已提交文件版本围绕项目组织 | 多人实时编辑光标、自动合并冲突、所有文件实时保存版本 |

## 六张新图的具体方向

共同视觉规则：使用当前首页的深藏青和克制科技蓝；青色、柔和紫色仅在重点关系上点缀。采用薄层界面的空间透视和软阴影，不用厚实体、芯片基座、机器人或玻璃立方体。画面主体不再被一个网页大边框包住，背景自然融入页面。保留足够间距，每图一个主焦点，最多两三个次要对象。图内不堆说明段落、加载骨架、操作按钮、悬浮链接或无意义小图标。生成图是概念视觉，不当作实际运行截图。

### 岗位数字员工：职责沉淀，形成可上岗的工作角色

一个占主体的专业数字员工身份与其工作资料/交付成果形成整体；旁边以较弱层次保留两种岗位角色，表现岗位体系与复用。工作方法、技能和资料以连续的薄层内容进入角色，而不是“头像卡片 + 五个图标”。人物可以使用生成的真实感职业头像，但不冒用真实人物。

主次关系：数字员工主体最大，职责/技能/资料是支持层，成果是小面积落点。模板是预制资产，数字员工是招募后的实例，构图不能把二者混成同一个角色。

### 多 Agent 协同：一个目标，专业分工，成果归集

一份主任务在画面上方或左前方展开为三条清晰的专业处理支路，支路等距且有共同方向，最后回到同一份汇总成果。支路使用可辨识的工作内容切片，如资料归集、分析判断和复核片段，不为每条支路套一整张桌面窗口。

主次关系：完整任务与最终成果构成主轴，专业分工是中段。不要把它画成一排 Agent 商店卡片，也不要生成几十个网络节点。

### 企业知识：资料成为回答与交付的依据

三层以内的企业资料与项目资料在后方汇聚，前方是一段简洁成果；一块被选中的原文片段与成果形成清楚对应。资料的轮廓、引用高亮和成果内容共同说明知识被使用。

主次关系：有依据的成果在前，知识材料在后。不是密集文档墙，不用巨大数据库圆柱和脑形发光物。

### 人机协作：围绕同一项目，把工作交接下去

一个开放的项目工作面由左侧材料、中间正在完善的成果、右侧的一次确认/交接记录组成；人物与数字员工头像出现在同一工作面上。仅保留一处简洁版本痕迹，说明成果可延续。

主次关系：共同成果是主体，人员参与是辅助。表达资料、会话、事项与成果有关联，不暗示未经确认的多人实时编辑。

### 系统集成：执行发生在现有业务对象上

中央为一个清晰业务对象或操作结果，左右后方为少量不同系统界面的切片，利用连续细线或统一内容轨迹说明同一任务跨越数据与业务动作。系统界面使用中性的业务信息结构，不把任意品牌 Logo 当作已支持连接器。

主次关系：已完成的业务对象/结果最清楚，外部系统是背景支持。不要把集成能力缩减成 Logo 墙；MCP/API/数据库与平台 OpenAPI 的调用方向不能混淆。

### 企业治理：授权边界跟随执行，全程可回看

同一个数字员工执行面上，前景为清晰任务记录，后方两层分别承载组织身份与授权范围；一条短而可读的执行记录贯穿其中。通过可见/不可见内容的层级、受控范围和记录秩序表达治理。

主次关系：业务执行仍然是主体，权限边界与审计记录支持它。不要用巨大盾牌、锁头阵列、证书徽章或“绝对安全”字样代替产品机制。

## 核心能力区的版式采用

用户已明确拒绝满屏大卡片，因此不把竞品出现卡片作为继续套卡片的理由。建议保留现有每项标题与正文完整性，改为共享页面底色的开放排版：较短的三项能力用三列文字组；四至六项能力用两列纵向条目。通过字号、字重、列间距和段间距建立层级，去掉每项独立圆角面板、阴影、图标容器与重复导语。

能力区与主视觉分工：主视觉讲一个最关键的关系，正文讲完整范围。不要把全部能力再次铺进图中，也不增加“了解更多”、外链箭头和小字说明。移动端按原有语义顺序单列，保留相同能力内容。

## 适用边界与核验

上述做法来自本次实际读取的公开页面及局部视觉资产，不代表穷尽同赛道，也不构成竞品实际交互、真人可用性或 TeGo 后台能力验证。品牌数量、客户数据、性能收益、资质、自动化等级与专有实现均不迁移。

图稿落地后应分别核对：是否在不读说明段落时仍能识别主题；是否与该页标题对应；是否保留正文已有的能力边界；六图是否统一材质与透视尺度；移动端是否仍能识别主焦点。技术压缩和响应式规格由实现阶段决定，不以下载到的竞品原图体积作为上线规格。


## 补充公开页面观察与实施判断

同日主代理使用浏览器实际访问百度图片的“AI Agent 企业协作 UI设计”结果，并打开 Linear 官网及 Agents 页面：

- 百度图片：https://image.baidu.com/search/index?tn=baiduimage&word=AI%20Agent%20企业协作%20UI设计
- Linear：https://linear.app/
- Linear Agents：https://linear.app/agents

百度图片返回大量结构图、卡通和多面板稿，没有把这些搜索结果直接作为设计结论。Linear 的实际页面中，工作内容、任务关系与共享工作画布更容易形成统一主体；其部分卡片布局不适用于本次用户要求。采用完整的工作对象、层级明确的内容与开放背景，不复制竞品界面、品牌和数据。

落地采用同一个深色系列、六个不同工作主题；每页只讲一个主关系。正文用左侧区块标题、右侧开放条目与细分隔线保留全部内容，不再给每项能力单独套圆角容器。没有增加装饰图标、箭头入口或说明卡片。原有联系入口、资源链接和相关能力路径保留。

## 生成与选稿

图像服务使用用户配置的 gpt-image-2；原始 PNG 均为 1536×1024。中文与英文各生成六页配图，中文页面不会使用全英文画面。简繁网站沿用同一中文图稿。完整最终提示词、源文件与上线 WebP 的对应关系保存在 capability-visual-assets_V1.1.json。

首批数字员工/知识图存在大文档、大字号或占位条问题，未接入页面。系统连接图前期将外部工具接入和平台 OpenAPI 画成一条回路线，后续版本虽分开方向但出现大图标和粗边框，均弃选。最终系统连接图只表达授权来源、数字员工与已完成跟进记录这一条关系，平台 OpenAPI 的独立调用方向保留在页面原有正文。

选择的图稿是能力概念视觉，不是实际 TeGo 运行截图。岗位头像为生成的人物形象，不代表真实客户或员工；协作图不含多人实时编辑光标。图中工作内容服务于当前页面主题，不新增网站之外的产品机制。

上线图使用 WebP、显式宽高和响应式图片构建流程，保留原始生成文件。图稿和技术检查结果不能代替真人可用性测试。


## 响应式配图与底色处理

浏览器复核发现桌面长图在手机上文字过细，系统连接图只占中央窄带，因此另行生成六页中英文方形图稿，保留主关系、减少辅助细节，手机端由 picture/source 选择对应画面。接口返回原始1254×1254 PNG，保存后生成1024×1024 WebP；图稿中所有指定主要文字仍有实际内容，不使用骨架条。

系统连接图采用方形主轴，在桌面和手机共用这一构图。其余五页桌面图对低亮度背景做平滑透明处理，去掉底色矩形和角落光斑；原始生成PNG均保留不改。所有最终生产图在capability-visual-assets_V1.1.json中记录尺寸、提示词与后处理方式。最终生产配图22个独立文件，按视口和语言选图，不会同时下载整组。
