# 国内企业官网解决方案叙事与视觉基准 V2.0

内部设计研究，2026-11-20。用于本轮银行、保险、证券、政务、央国企、信托、企业通用七类解决方案重构，不进入官网可见页面。

## 本轮结论

现页的问题不是配图数量偏少这么简单，而是四个业务主张没有各自的视觉证据。顶部的一张前后对比图只能说明整体改变，不能替整页解释四个不同业务难题。后面四段文字因而变成了观点罗列，客户无法看到改变具体发生在哪里。

本轮应采用“一个行业主张、四个价值专题、四种独立图形叙事”的详情页。每个专题必须同时回答：哪一个业务矛盾正在损耗专业工作，企业投入后可以获得什么改变，图中哪些具体内容能支持这个改变。整页不以产品配置、操作步骤、岗位招募流程为主线。

最值得结合的参考是神策银行的专题分层、观远零售的业务结果锚点、金蝶财务云的人机职责区分。三者值得借鉴的是内容组织，不能把它们的 UI、紫色三维漏斗、客户数据或客户成果复制为 TeGo 的资产。

## 研究范围与方法

实际阅读了 16 家厂商的官网页面正文，其中包含行业解决方案、跨行业场景方案和财务产品方案。另对神策、飞书、观远、金蝶进行了浏览器分区视觉检查，保存 4 张截图。该清单是已核查的样本，不表述为穷尽国内所有 ToB 官网。

检查维度为首屏主张、痛点的具体程度、主题分层、图片承担的信息、业务收益、证明材料、采购入口。所有判断区分“网页确实展示的结构”和“本轮针对 TeGo 的设计推论”。来源与制作依据仅保存在本研究，不添加到官网的页底小字。

## 对本站当前实现的诊断

读取到的共享模板 `src/features/solutions/shared/IndustrySolutionPage.astro` 只有一个 `figure`，后面统一排列四个 `article`。数据里的 `problem` 和 `outcomes` 未进入独立业务画面。于是每个专题缺少可被扫读的业务对象，产生“一张概览图加全文字”的效果。

`tests/industry-solutions.test.mjs` 还明确要求“只有一个图”，并禁止 `feature.image`。这条回归约束已经与用户最新要求冲突，必须与新结构同步修订。应验证四个价值专题均有独立可用图片、中英文内容与资产齐全，不能再将单图布局锁定为正确行为。

当前首页与总览共享详情的概览图本身没有问题。它们承担快速发现行业的职责，详情承担展开业务改变的职责，两者不应使用同样的信息密度。

## 详情页的新信息结构

### 首屏：业务改变

保留行业环境背景与明确行业名称，以两行标题表达企业希望得到的改变。正文承接其业务冲突，不讲平台模块清单。采购入口使用既有共享按钮。

首屏不附加眉题、行业数量、更新日期、脚注、索引说明或重复导流。

### 总览：让客户先看懂方案方向

可保留现有正视的行业前后对比总览，但缩回“概览”职责。两个状态有真实间距，通过数字员工专业支撑与单向箭头相连。所有文字水平，不能斜切、旋转或透视。

该图不必出现整页所有内容；它只需要在一次扫视中说明主要业务阻力与总体改善。

### 四个价值专题：每个都能独立成立

每个专题包括一个收益主张、两句有行业对象的业务正文、一幅独立完整业务图。正文约 70–110 个汉字，不再依赖额外说明卡片。图中使用极少但真实的业务名词，表达“专业工作发生了什么改变”，不绘制产品操作流程。

四个专题按语义选择构图。可以分别采用证据关系、时间脉络、范围影响、组织扩散。左右交替只是版式节奏，不能用换边来假装内容变化。重点主题可采用全宽图，其他主题图文并排；移动端按照标题、图片、正文的顺序保持完整。

图片是专题主体，至少占桌面该专题可用宽度的一半。不能出现大量小卡片、四种相同报告、整页同角度 UI 或无内容的灰条。图像必须让不了解产品的人能够指认业务对象、受阻点与改善结果。

### 部署与治理：作为企业采购判断

保留私有部署、数据授权、审阅审计等已确认能力，以具体部署关系作为收尾支撑。它回答企业能否在现有组织与数据边界里使用方案，不再重复四个业务收益，也不扩展成产品配置教程。

不伪造客户案例、客户姓名、商标授权、评价与百分比成果。官网已有且经用户明确确认的业务口径按原授权使用；其他公司的证明只能留在内部研究。

## 七行业的独立图形叙事建议

下表是本轮原创设计建议，不是对参考厂商实际功能的转述。最终画面文字以各行业内容负责人确认的正文为准。

| 行业 | 第一专题图：核心专业矛盾 | 第二专题图：变化的连续性 | 第三专题图：组织规则的落地 | 第四专题图：专业能力的扩展 |
| --- | --- | --- | --- | --- |
| 银行 | 财报、送审说明与授信依据汇聚到同一疑点；差异指向经营实质和偿债来源 | 客户经营变化接上历史核查，显示风险演变而非孤立预警 | 外部条款变化影响到具体本行制度与责任条线 | 本行经确认的审查方法支撑多个分支机构，同类问题有共同判断依据 |
| 保险 | 投保告知、医疗材料和责任约定之间的专业疑点被清晰对应 | 同一保单的补充材料、沟通与处理意见连续接续 | 条款、规则、口径落到核保或理赔的具体问题 | 经验从专家个人转为可获得的专业依据，保留核保理赔人员判断位置 |
| 证券 | 投研观点与公告、财报、研究依据关联，突出证据与观点的差异 | 发行人事件、持仓关注与历史判断串联，专业人员看到变化影响 | 合规要求对应具体业务材料与责任岗位 | 机构研究方法和客户经营知识服务不同团队，避免单纯画行情终端 |
| 政务 | 政策条款、申请事项与办理条件相互核对，呈现跨口径解释冲突被解开 | 群众或企业的一件诉求跨次沟通仍保持同一事项背景 | 制度变化落到材料要求、部门责任和答复依据 | 专业办理经验支撑更多窗口与人员，避免以智慧城市地图代替价值 |
| 央国企 | 集团制度、业务事项与分支材料被对照，穿透专业审阅盲区 | 项目或经营问题的变化接续，管理层看到异常背景和处理进展 | 制度要求对应合同、采购、决策事项中的具体依据 | 总部专业方法支撑下属单位，展示集团知识复用而非组织架构本身 |
| 信托 | 信托合同、底层资产与尽调依据对应，显露结构和风险关注点 | 存续资产变化接上设立时判断与历次管理记录 | 受托职责、合同约定与披露材料相互校验 | 产品与资产专业经验在项目团队间复用，区别于银行财报审查图 |
| 企业通用 | 客户需求、项目资料与专业方法聚合为可审阅的方案成果 | 同一业务任务的沟通、修订与成果持续接续 | 企业制度与业务授权清晰落在工作范围 | 成熟岗位经验支撑更多团队作业，区别于仅用六个人像表示团队规模 |

每行的四幅图要使用不同的图形语法。即便采用同一蓝黑色系，也不能把四幅都画成“左侧输入三张纸、右侧输出一份报告”。

## 业务图验收

1. 单独打开图片，不读旁边正文，能说出它解决哪类业务问题。
2. 遮住标题后，仍可区分银行、保险、证券、信托的业务对象。
3. 图中有明确的受阻点与改善关系；不是一份报告被画得更漂亮。
4. 不使用任意经营增长、准确率、节省时长等虚构数字填充画面。
5. 每个有文字的区域有具体内容，不出现骨架条、伪文字、随机曲线与无业务意义节点。
6. 前后对比保持正视，两个画面之间确有衔接；图内不出现编号式操作流程。
7. 各图色系、笔触、字号层级一致，构图按业务语义变化。
8. 专业人员的审阅判断是业务关系的一部分，以画面主体呈现，不加免责声明小字。
9. 不用卡通人物、机器人、塑料三维、厚玻璃、金属舞台与强反光取代专业表达。
10. 没有独立顶部装饰横线、页码、来源脚注或制作说明。

## 工程验收建议

- 各行业至少四个独立专题图片路径，允许保留一张概览图；所有图片必须实际存在。
- 中文与英文拥有同样的专题数量、业务含义与完整资产，不通过切换语言恢复旧版单图结构。
- 首页、方案总览继续读取同一行业价值数据源，详情从相同源展开专题。
- 保持既有一体机页面、首页八大领域图与共享 CTA 规范。
- `npm test` 验证新专题和资源完整性；`npm run build` 验证站点构建。
- 在实际页面检查桌面与移动端，不以源文件存在代替阅读效果；检查标题、图片与正文之间的层级和留白。

## 研究材料使用边界

本轮借鉴叙事方法、页面层级和业务具体化方式，不复制参考站图片、报告、客户素材或成段营销文案。各厂商公开成果仍归属于其自身；TeGo 页面只使用本产品经确认的能力与用户明确提供的业务口径。

配图验收的核心是业务改变可见，数量仅是完整性门槛。四张无关图片、四份相同报告、四块抽象科技卡片，都不算完成。
