# 政务与央国企行业主线复核

访问日期：2026-11-15，Asia/Shanghai。范围为首页政务、央国企 Tab 与对应行业内页；首页布局和已确认图片不变。本记录保留公开观察、采用判断和产品边界，不进入页面小字。

## 结论

政务不能只以“政策检索、文稿、会议纪要”代表全行业。政府公开应用已经形成三条业务链：政策条件与服务对象匹配，咨询导办与申报材料预审，诉求识别与跨部门办理跟进。政策研判、会议督办和综合文稿仍有价值，应保留为支撑工作，而不是首页唯一主线。

央国企不能只把资料“归集成汇报”。业务负责人关心集团经营变化发生在哪个单位、招采条款和证明材料有哪些缺口、项目进度与成本偏差如何跟进、隐患整改是否有责任人与证据。已有招投标、EHS 插件及授权数据分析、项目事项和知识能力，能围绕这些对象组织方案；各企业系统的接入、作业规则与权限仍按项目配置。

## 政务：真实业务问题与采用

### G1 中国政府网：从咨询到申报、诉求办理与政策兑现

来源：[AI 相助，政务服务跑出“智能加速度”](https://www.gov.cn/lianbo/difang/202503/content_7015236.htm)。原文来源人民日报，发布时间 2025-03-24 07:53；本次已阅读全文。

正文事实：

- 深圳“深小 i”围绕创业补贴等具体需求提供申请流程、补贴范围和办事指引；知识来源结合各级政策、实际案例与办理规则。
- 苏州相城的商事登记帮办导办，将口述信息组织为申请材料；昆山 12345 场景识别诉求类型、时间、地点、人物等要素，辅助工单分类与派发。原文明确指出人工逐条阅读耗时，多部门工单容易派错。
- 杭州西湖“西小服”把企业需求送到相应部门的信息系统；政策拆成多项条件后与企业标签匹配，服务不止是解读文件，而是接到具体需求和政策兑付。

采用：页面围绕“政策适用条件—对象资料—办理清单”“指南要求—申请附件—补正清单”“诉求要素—职责目录—分办建议与办理反馈”表达工作。这样既能展示行政服务价值，也有明确输入与交付对象。

限制：TeGo 当前资料可支持知识检索、文件核对、结构化整理、项目事项与授权接口组合；本次没有验证 TeGo 已原生接入 12345、商事登记或政策兑付系统。因此不写成全市工单自动派发、免申即享到账或自动审批；外部案例中的效率比例不移植。

### G2 深圳政府在线：政务八类场景的全链条拆解

来源：[宝安以八大智能应用场景推动“人工智能+政务服务”落地见效](https://www.sz.gov.cn/cn/xxgk/zfxxgj/gqdt/content/post_13017242.html)。信息来源宝安区，发布时间 2026-10-12 17:58；本次通过 URL 正文获取读取全文。

正文事实：

- 智能申报直接回应“填表多、材料繁、反复改”：申报指引、表单预填、材料核验、条件预审共同组成作业链。
- 政策匹配以企业概况、经营情况等信息形成画像，与政策条件匹配；诉求通过内容识别提取关键信息，企业端、工作人员端、领导端和后台共用办理进展。
- 智能预警围绕民生诉求的分级识别、提前介入和规范回复；智能办公只是八类中的一类。
- WorkBuddy 在 18 个部门试用的原文除了文稿与表格，还明确提到政策口径比对、企业尽调及奖补对象配对。

采用：政务首页六场景建议为“政策落实、惠企匹配、办事导引、材料预审、诉求研判、督查督办”。内页新增政策适用与诉求治理，把原有材料初核改为完整的办事导引与申报预审；会议和文稿能力保留。

限制：文中“自动审批、免申即享、视频勘查、身份核验”依赖专门的政务业务平台与数据体系，不推断为 TeGo 已有原生功能。公开案例中“未来继续推出”的事项不当成已完成事项。

### G3 龙华区政务服务和数据管理局：政策服务与城市治理并行

来源：[龙华区发布多个“DeepSeek+”应用场景，全面赋能数字政府建设](https://www.szlhq.gov.cn/lhzwfwj/gkmlpt/content/12/12014/post_12014919.html)。发布机构为深圳市龙华区政务服务和数据管理局，发布时间 2025-02-17；本次已获取完整正文。

正文事实：政策 AI 计算器包含企业条件导办、政策文件导办、补贴事项导办、政策推荐和政策月历；虚拟园区连接找政策、人才、空间、政务、资金、市场等服务。城市治理与安全生产另有智能巡检场景，识别事件后预警并推送业务部门。

采用：不能把政务缩为机关办公，首页应同时出现企业群众服务与治理任务。治理部分采用诉求材料、事件记录及办理进展的研判与协同，而非只做一份舆情摘要。

限制：视频巡检、视觉算法、人员定位不是本仓库已证明的 TeGo 原生能力；不把第三方识别结果的接入写成 TeGo 自身完成现场感知。

## 央国企：真实业务问题与采用

### S1 中国华电：招采需要审查、编制、监管和供应商信息共同支撑

来源：[中国华电：深化智能招采实践，构建阳光高效招采体系](http://www.sasac.gov.cn/n4470048/n22624391/n23826238/n23826274/n23859376/c35426557/content.html)。国资委网站，文章来源中国华电集团有限公司，发布时间 2026-05-12；本次已阅读全文。

正文事实：

- “华电·智采”与采购计划系统、电子招投标系统集成；统一范本、评审要素、投标模块和数据标准是基础。
- 文件初审处理资格、符合性、商务、技术四类要素，完成文件解析、条款定位与符合性审查，形成清标报告和初评意见，专家复核争议点。
- 编标按项目基础信息匹配品类范本、参数、资格条件和评审规则；供应商画像归集资质业绩、交易、履约、信用惩戒及舆情。
- 原文还区分已试运行的六大场景与后续年度建设安排，不能把远期目标并作现状。

采用：原内页“投标响应矩阵”保留，并补足采购文件审查这一采购人侧工作。场景名称采用“招采文件审查与投标响应”，展示条款、资质、技术商务材料的匹配、差异定位及响应编制。

限制：外部案例有专门的评审模型、数据集和业务系统。TeGo 不因此增加已通过行业评测的自动评分、围串标定性或供应商全面实时征信承诺。本页不引用其项目数量、准确率和效率数字。

### S2 重庆市国资委：经营分析要落到风险线索和处置

来源：[数据穿透，预警直达，重庆国资监管迈入“AI+”时代](http://www.sasac.gov.cn/n2588025/n2588129/c35168437/content.html)。国资委网站，文章来源重庆市国资委，发布时间 2025-12-25；本次已阅读全文。

正文事实：统一数据交换平台汇集监管数据；“财务风险识别”和“经济运行分析”Agent 围绕经营活动开展研判，覆盖财务、债务、投资等领域。公开实践将异常预警与调度处置连接，管理关注点是从层层上报、事后问责转向过程干预。

采用：原内页“集团经营材料归集”应改为“集团经营分析与问题督办”，保留口径归集，进一步交付预算执行差异、重点单位异常线索及督办事项。围绕已有授权数据查询分析和项目事项实现，不把“写一份汇报”当作终点。

限制：该监管体系历经多轮建设，本次没有证据表明 TeGo 已具备同等全级次实时穿透与市级风险模型；页面不移植其覆盖率、资金规模或实际处置成果。

### S3 中建五局：进度、履约与成本是项目管理主线

来源：[改革进行时丨中建五局：推动数字化转型，赋能产业链协同](https://5bur.cscec.com/5bur/oa/dtxw/202412/3847718.html)。中国建筑第五工程局官网；正文标注发布日期 2024-03-29，虽然 URL 路径含 202412，记录按正文日期；本次已阅读全文。

正文事实：

- 项目全过程管理以进度为主线、任务为驱动；工期节点任务化管理，预警信息推送，履约按主题和指标分级管理。
- 合同、任务单、结算、支付、财务凭证关联后归集成本，区分收入成本、目标成本和实际成本，处理信息滞后与经验依赖造成的偏差。
- 经营看板、项目全成本分析和跨系统业务资源共享共同支撑管理，而非只管理项目文件。

采用：把原“项目协同与安全工作”拆成“项目履约与成本跟进”和“安全隐患与整改跟进”，保留原项目交付包与版本协作。项目部分通过输入合同、节点计划、进展和成本资料，交付进度差异、成本差异和协调事项。

限制：这是央企数字化实践，部分为传统业务系统与检测设备能力，并非每一环都是生成式 AI。TeGo 可接入相应记录并开展分析协作，不因此宣称替代其造价系统、现场设备或自动工程验收。

### S4 国家管网：安全价值来自隐患、作业与整改的衔接

来源：[聚势赋能，打造“5G+安全”服务品牌，以数字化转型助力企业高质量发展](http://www.sasac.gov.cn/n4470048/n29955503/n30329277/n30329358/c32230467/content.html)。国资委网站，文章来源国家石油天然气管网集团有限公司，发布时间 2024-12-02；本次已阅读全文。

正文事实：LNG 接收站面临环节多、风险作业多、监管人员少、作业信息分散的问题；案例结合现场数据、风险作业管理、应急数据共享与人员协同，强调规则固化、历史经验沉淀和审批提醒。现场视频、物联网和机器人是专门基础设施。

采用：安全场景应直接呈现检查记录、隐患、责任时限、整改反馈和证据，将检查问题接到整改复核。TeGo 已有 EHS 材料整理方向，可形成隐患整改台账与待复核事项，衔接责任人采纳。

限制：不写成平台自身检测气体泄漏、实时定位人员、远程控制设备或保证现场安全；这些依赖现场系统和专用硬件。

### S5 厂商交叉核对：已有案例与未来规划分开

来源一：[拓尔思：实战派 Agent 落地应用案例（四）](https://www.trs.com.cn/ljwm/xwhd/202507/t20250729_10571.html)，正文发布时间 2025-07-29。已阅读全文。正文列出供应商“只进不出”、资质难核、信息不足、关联方缺位与知识难用等痛点，采用数据、风险、报告等专业 Agent 分工。客户为未具名央企，属于厂商案例表述；采用供应商信息动态核对与专业分工思路，不声称已独立验证其“效率翻倍”。

来源二：[致远互联：中建一局协同运营案例](https://www.seeyon.com/News/desc/id/8524.html)，正文发布时间 2025-12-29。已阅读全文。已实施部分是统一入口、分级管理、公文印章和项目财务人力系统集成；“建筑行业管理大模型、AI 风控、智能推演”位于“未来展望”。采用集团分级协同和接续现有系统的思路，不将其未来规划作为已上线 AI 成效。

- 两个既有行业 `content.ts`：原政务政策研判、会议督办、材料初核，原央国企招投标、集团经营、项目安全、制度文书全部保留。

采用范围是“可组合落地的行业工作方案”，不是新造一个已完备的行政审批系统、国资监管平台或工业控制系统。系统连接和业务规则放在既有实施正文中说明，不另加条件小字。
