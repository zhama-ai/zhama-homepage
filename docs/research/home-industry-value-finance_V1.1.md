# 金融行业方案二次调研：证券与保险核心作业链

访问日期：2026-11-15（Asia/Shanghai）。本版补正 V1.0 将证券过度聚焦财富经营、保险过度聚焦材料与续期的行业框架。旧版保留，仅本版结论用于证券、保险内容调整；银行由主任务另行研究。

## 本次采用的判断

证券主线应为投研、合规风控与客户经营，财富经营分析是其中一个有价值的工作方向。保险主线应为核保、理赔与保全，产品知识、销售支持及续期属于相邻服务工作，不能代替核心运营。

页面以“业务问题—输入—处理—成果”表达方案。成果不能全部退化成泛化文档：证券要形成研究依据、合规问题定位、风险线索及客户行动；保险要形成核保风险要点、理赔事实与责任对照、保全变更前后差异及办理交接。它们可通过工作表、项目成果和授权系统操作承接，而不是单纯生成一份材料。

行业案例说明可借鉴的工作方法，不能证明 TeGo 已具备案例机构的专用模型、金融系统、客户及量化成效。TeGo 当前页面可核对的基础包括知识与项目资料检索及引用、岗位技能、专业 Agent 分工、文件成果、人工回应、项目版本，以及分别配置认证和权限的 MCP、RESTful API、数据库与业务插件连接。核保模型、理赔定损、自动授信、实时交易阻断与专用反欺诈模型均不据外部案例写为平台原生功能。

## 检索与阅读方式

通过公开 Exa 搜索检索证券投研、合规风控、客户经营，以及保险核保、理赔、保全的机构与厂商案例，再逐一打开并阅读 HTML 正文。优先机构官网与厂商具体案例。证券部分同时采用行业协会转载、机构负责人访谈及企业官微署名转载，并在下方标明来源性质。没有把搜索摘要视为完整案例。

### 证券：研究信息如何进入客户服务与风控工作

1. [中国证券业协会：东方证券以“东方大脑”打造数字金融新范式](https://www.sac.net.cn/hydt/202606/t20260629_81856.html)，2026-06-29。协会页面注明摘自证券时报，属于协会收录的行业报道，并非东方证券官网自发案例。
   - 实际做法：研究报告解读、因子挖掘、智能问数问价、重点观点抽取；客户画像与个性化服务；多维预警、舆情研判和私募尽调问答；信用主体监测、知识图谱及 AI 辅助合规监控。
   - 采用：投研、风控与客户经营三类工作并列，研究结果要进入业务协同。
   - 边界：文末深度个性化财富 Agent、跨市场实时风险体系明确是未来攻关方向，未写为已部署。客户数、资产规模和效果数据不迁移。

2. [恒生电子官微署名文章：大模型如何赋能券商发展](https://finance.sina.com.cn/stock/relnews/cn/2025-04-17/doc-inetmzcw2431080.shtml)，2025-04-17，新浪转载企业官微原文。
   - 实际做法：中国银河证券以微信机器人处理协议交易的询报价理解、错误处理与报价整理；投资监督系统通过大模型把监督规则解析为标准指标库、解释风控条款。国金证券介绍研报因子加工、新闻公告负面情绪过滤、产业链挖掘；东吴证券介绍研究销售知识图谱及投资顾问应用。
   - 采用：合规风控不能只写“复核文字”，要包含规则解析、适用条款定位、风险主体与事件线索整理；客户经营要有可用的服务背景和下一步行动。
   - 边界：文章中“可支持”或交流探索的反洗钱、异常行为监测、投行审阅不视为已部署。协议交易机器人不等于 TeGo 已接入交易系统。

3. [财联社对长江证券及研发团队的访谈：研究旗舰店](https://www.cls.cn/detail/1805252)，2024-09-22，机构负责人受访的行业媒体实访。
   - 业务问题：研究报告海量、客户需求多样、筛选有效信息耗时；研究员机械准备工作挤占深度研究。
   - 实际做法：以长江证券研究内容为基础开展问答与研究服务，语音转录、资料理解与信息提炼；只服务白名单客户，按授权访问。总量与行业数据库在文中是后续计划，不写成当时已具备。
   - 采用：投研成果要保留研究框架和可引用依据，客户服务基于授权内容与客户需求，而不是泛化“AI 写研报”。
   - 边界：这是外部产品，不使用其客户或实施效果作为 TeGo 背书。

4. [讯兔官方：大型保险资管投研管理系统](https://www.rabyte.cn/detail.php?id=237)，2024-03-01；[讯兔官方：投研管理体系升级案例](https://www.rabyte.cn/detail.php?id=239)。
   - 业务问题：路演通知散在邮件与电话、报告缺少分类全文检索、人员反复从邮箱网盘微信整理 Excel、指标数据重复购买且无法共享。
   - 实际做法：路演集中管理；内外部报告按公司、行业、类型整理；邮件研报入库；多源资料清理与指标共享；研究图表可进入报告；服务记录成为评价依据。
   - 采用：研究准备要形成可复用的专题资料、指标图表和观点依据，并接上研究协作。
   - 边界：首篇是未具名保险资管的买方投研案例，仅借鉴研究作业，不称券商案例；其 ETL 和投研数据产品不写成 TeGo 已有原生功能。

### 保险：从核保、理赔到保全的不同处理对象

5. [中国人寿官网：加速拥抱 AI，万亿保险央企的数智蝶变](https://www.e-chinalife.com/c/2026-10-12/4a681fdd-bcc3-4c7c-88dc-ce6b7ae0cff8.shtml)，2026-10-12，第一方。
   - 核保：长险新单智能审核模型、数智预核 Agent、重疾险 AI 模型、投保信息校验。规则清晰且材料完整的标准工作由系统处理，人员转向复杂核保、异常识别与个性化服务。
   - 理赔：意外险、重疾险责任辅助判定与信息分析；一站式理赔直付；案件处理的跨区域调度接续。
   - 保全：智能审核，贯穿保单全生命周期的数据持续更新。
   - 销售服务：培训素材和客户服务方案；语音直达服务、企业微信与线上线下协同。
   - 采用：保险方案不能等同于补件和续期；必须分别呈现核保风险信息、理赔事实与条款、保全变更与作业交接。
   - 边界：专用核保、责任判定、反欺诈、反洗钱与数字审计模型为中国人寿自有建设，不迁移为 TeGo 原生系统；各项审核率、时效及规模不迁移。

6. [中国人寿官网：全周期服务与保全流程升级](https://www.e-chinalife.com/c/2022-12-28/531080.shtml)，2022-12-28，第一方。
   - 实际做法：多渠道服务入口融合，保单借还款、进度查询、线上处理轨迹、多身份服务场景、统一审核与作业标准，线上自助与远程交互办理衔接。
   - 采用：保全是保单存续期变更与服务作业，不是“续期提醒”的同义词。页面需要办理事项、当前保单、变更前后内容、所需依据与后续处理状态。
   - 边界：引用其作业拆分方法，不宣称 TeGo 已直接办理保单借款、扣款或资金支付。

7. [中国人寿官网：重庆全链条理赔与数字服务](https://www.e-chinalife.com/c/2024-07-05/f6618a2e-eec2-4224-95f1-1a2a49575efe.shtml)，2024-07-05，第一方。
   - 实际做法：多渠道线上受理、智能处理、支付贯通；保全触点与审核升级；企微、公众号和 APP 承接咨询与理赔服务。
   - 采用：成果要能接续业务处理，而不是只有一张摘要；客户服务应贯通资料、事项与进度。
   - 边界：支付、赔付率、时效不迁移。

8. [艺赛旗官方转述人保财险：“卷王”来了](https://www.i-search.com.cn/html/news/2023/1016/15447.html)，页面内部日期 2023-04-19，正文注明来源人保财险；URL 日期与正文日期不同，按正文记录。
   - 实际做法：RPA 与 OCR 辅助车险核保信息检查；理赔照片抽取、分类归档及二次复核；农险保单系数批改、影像上传、理赔资料下载。
   - 采用：核保、理赔和批改拥有不同的数据对象和可交付处理结果，不能合并成一个“资料完整性检查”。
   - 边界：这是 RPA/OCR 案例，不作为生成式 Agent 已落地证明；不迁移其无人作业与效果数字。

## TeGo 映射与实施边界

核对站点当前 `src/data/pages.ts` 与产品落地页：岗位方法可封装为技能；知识与项目资料按授权检索并引用；专业 Agent 可分工；文件与人工反馈在项目中形成版本；外部系统通过已配置的 MCP、RESTful API、数据库或业务插件连接。

因此以上是围绕企业业务知识、规则与系统建设的方案范围，不能冒称已经安装的券商交易系统、保险核心系统或开箱即用的金融风控引擎。页面 scope 保留一处配置与专业决策边界，不把内部研究过程、缺口或泛化解释散落成小字。项目需要写回客户系统时，须有明确接口及授权；没有连接时以已核对的项目成果承接，不伪称已办理。
