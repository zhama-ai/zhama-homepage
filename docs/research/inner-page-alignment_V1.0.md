# 内页对齐：公开研究与实施判断

访问日期：2026-11-15。首页为已确认基准。本记录是内部研究，不是客户案例、产品实测或真人可用性测试。

## 本次判断

内页问题不仅是图片风格混乱。银行入口承诺信贷业务、保险入口承诺理赔续期，正文却主要讲通用材料整理，业务承诺与内容不一致。行业页应先说明决策者面对的业务问题，再给出具体作业与成果，最后说明承接这些作业的资料、方法、连接与协作。避免用“摘要、草稿、清单”替代成果价值。

视觉沿用首页深色画布、克制蓝青点缀、适量留白和可读字号。每幅视觉只表达一条主要业务关系；主体是内容完整的业务成果或产品能力，不使用空横条、加载式占位、伪文字、装饰大屏、无关机器人和金属物件。使用 HTML/SVG 精确排版业务内容，可保持中英文清晰和移动端阅读，不将其称为产品实际截图。

## 内容与能力映射

事实基线：`src/features/pricing/content.ts`、当前产品介绍、FAQ及各能力页。现有能力包括独立数字员工、模板、主/子Agent、技能与插件、知识检索和引用、项目与事项、版本、定时任务、多端、MCP、RESTful API、数据库、平台OpenAPI、企业治理与私有化。业务系统的接入、字段规则、行业模板随项目配置，不冒充预装成品。

| 页面组 | 现状 | 对齐方向 |
| --- | --- | --- |
| 首页 | 已确认 | 保留布局、文案与配图；内部核对行业承诺，由内页承接 |
| 证券/银行/保险/政务/央国企 | 同一生成图重复使用；行业问题弱；通用卡片重复 | 行业问题→作业过程→有业务用途的成果；行业专属内容与成果视觉 |
| 通用办公 | 场景有效，视觉通用 | 保留方案、CRM、周期工作，使用完整的任务交付视觉 |
| 产品六能力页 | 多种概念图、节点图混用；部分文字过于抽象 | 每一能力有明确对象：岗位配置、分工任务、连接调用、项目交接、知识引用、授权审计 |
| 产品总览/生态/企业 | 同一生成图与大图标复用 | 按产品协作、能力发布、企业控制分别表现；保留完整能力条目与原锚点 |
| 方案总览 | 复用首页式图片，但无法看出交付差异 | 按行业选择，直接看到该行业的工作成果与场景 |
| 互联网与泛行业 | 已有独立交互场景和前后对比 | 保留有效覆盖，核对与本轮共用规范及平台事实；不在无对应调研时重写整页 |

| 报价/下载/资源/FAQ/博客/联系/法律 | 多为原生内容及功能页面 | 保留功能与有效内容，复用统一背景和字号；不为追求统一而删除内容 |

## 本轮落地标准

标题直接说明业务结果；每项场景有具体资料、动作和交付；行业差异来自业务，不只是名称替换。视觉上的文案与页面标题对应，中英文一致。不新增客户背书、效果数字或未经实现核对的原生功能。

本轮验证使用源码审阅、类型检查、构建、站点链接检查与实际浏览器检查。自动化和AI检查不等于真人可用性测试。
